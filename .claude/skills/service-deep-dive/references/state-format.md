# Формат заметки `state/services/<name>.md`

Память скилла — рабочее состояние знания о сервисе. Не журнал.
**Коммитится в git** — это shared артефакт команды, не приватная
память агента.

Заметки лежат **рядом со скиллом**, не в `docs/project/services/`:

```
.claude/skills/service-deep-dive/state/services/<name>.md
```

Дальше — короткое `state/`, это сокращение того же пути.

## Шаблон

```markdown
---
kind: service
name: backend
ref: docs/project/services/backend.md
---

## Открытые вопросы
- Какой именно tag-формат: semver (`v1.4.2`) или sha-prefix (`abc1234`)?
- Backup-расписание для backend-volume — нужен ли вообще? (**blocker**)

## Доменные решения
- Healthcheck = `/healthz`, не `/`, потому что корневой роут отдаёт
  ландинг через CDN; `/healthz` явно отвечает backend-инстанс.

## Что копать дальше
- Раскрыть KV-поля `jwt` после seed'а через /request-secret.
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | `service` | избыточная подсказка читателю + быстрый фильтр |
| `name` | равен `name` сервиса в frontmatter md | связь с артефактом |
| `ref` | `docs/project/services/<name>.md` | удобная ссылка в редакторе |

## Секции

Все три опциональны. Любая отсутствует, если содержимого нет.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка списка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — вопрос блокирует
  переход `draft → stable`. Без префикса/суффикса — открытый, но не
  блокирующий.
- Закрытый вопрос **удаляется** из секции (не зачёркивается, не
  переносится в «решено»). Если стало пусто — удалить всю секцию.

### `## Доменные решения`

Список неочевидных смысловых решений, которые не помещаются в md
сервиса, но важны для будущих сессий.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было X, стало Y», без дат,
  без отсылки к прошлым попыткам.
- Если решение уже растворилось в md сервиса (Hosting/Identity/...) —
  удалить отсюда (не дублировать).

### `## Что копать дальше`

Список локальных «следующих шагов» по этому сервису.

- Не путать с открытыми вопросами: «копать дальше» — задача архитектора;
  «открытый вопрос» — конкретный неясный смысл.
- При выполнении шага — удалить строку. Если стало пусто — удалить
  секцию.

## Правила жизненного цикла

- **Создаётся** только когда есть что записать (хотя бы одна непустая
  секция).
- **Перезаписывается** свободно — это рабочее состояние.
- **Коммитится** в git — каждая значимая правка идёт в commit вместе с
  правкой `services/<name>.md` (или отдельно — если правится только
  state). Это shared контекст команды.
- **Ревьюится** в Pull Request как обычный артефакт.
- **Удаляется** через `git rm`:
  - Все три секции пустые → удалить файл целиком (commit «chore(state):
    drop empty state for service/<name>»).
  - Запись `services/<name>.md` удалена (каскад) → удалить и state.
- **Не аккумулировать** журнал: «было/стало», даты, «решено такого-то»,
  «обсуждено» — не должно быть.

## Что коммитим / что НЕ коммитим

✅ Коммитим:
- Открытые вопросы (включая `**blocker**`-маркеры).
- Доменные решения с обоснованием.
- Что копать дальше.

❌ Никогда не пишем сюда (значит и не коммитим):
- Значения секретов (паролей, токенов, KV-полей). Если упомянуть надо —
  только путь `kv/projects/<p>/<env>/<kind>` без значений.
- Содержимое `.env` или rendered конфигов из `.runtime/`.
- Личные данные оператора (хост, IP, путь домашней папки) — это
  `.env.local`-зона.

## Что НЕ хранить в заметке

- Историю изменений (это git).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого md (`name` → md, `subtype` → md, поля
  `Identity/Secrets/...` → md).
- Доменные термины и формулировки от модели «на всякий случай».
- Альтернативы, которые рассматривались, но забыты, — если они не
  «доменное решение» с обоснованием.
- Ссылки на внешние материалы и транскрипты — это сырьё для режима B,
  не память.
- Cross-repo next-steps, которые относятся ко всей сессии — они в
  чате-резюме завершения, не в state одного сервиса.
