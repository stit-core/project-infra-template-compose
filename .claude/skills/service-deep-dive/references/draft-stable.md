# Контракт `draft → stable` — service-deep-dive

Запись становится `stable`, когда **все 6 пунктов одновременно** ✅.
Скилл проверяет, архитектор подтверждает, скилл применяет.

## Чек-лист

### 1. Frontmatter валиден

- `id == "project.<name>"`.
- `kind == "service"`.
- `name == basename(file)` без `.md`.
- `subtype` ∈ {`backend`, `frontend`, `datastore`, `infra`}.
- `hosting` ∈ {`here`, `external`}. **`external` → service-doc не должно
  существовать вообще** (только строка в `stack § Service map`); если
  файл есть, это рассинхрон, требует каскада.
- `status` ∈ {`draft`, `stable`}.

Программная проверка — `make project-check A=docs/project/services/<name>.md`.

### 2. Все 5 H2 присутствуют и непусты

- `## Hosting`, `## Identity`, `## Secrets`, `## Route`, `## Generates`.
- Placeholder `<...>` (как в `_templates/service.md`) **не считается**
  содержимым.
- Опциональные значения — `N/A` явной строкой (для `Secrets` сервиса
  без секретов, для `Route` чисто internal).
- Программно проверяется тем же валидатором при `status: stable`.

См. `field-checklists.md § <kind>` — что считается «непустым» по каждой
секции.

### 3. Все ссылки валидны

| ссылка | где | как проверить |
|---|---|---|
| KV-kind в `Secrets` | имена `db`/`minio`/`backup`/`jwt`/`oidc`/`meta`/прочее | kind читается существующим vault-agent template'ом (`configs/vault-agent/templates/*.tpl`; шаблоны именуются по consumer-сервису: `db` рендерят `postgres.env.tpl`/`backend.env.tpl`) ИЛИ явный stub-next-step «через /request-secret» |
| vault-agent template имя | `Secrets` | то же |
| `<sub>.${DOMAIN}` в `Route` | публичный сервис | сабдомен упомянут в `stack.md § Domains` ИЛИ явный stub «допилить stack» |
| `COMPOSE_PROFILES`-профиль в `Hosting` | имя профиля | соответствует таблице маппинга `subtype → профиль` (см. `docs/project/README.md`) |
| `Generates` имена parts/templates | имена | реалистичны для kind (`agent.hcl.parts/<part>.hcl`, `templates/<svc>.env.tpl`, `compose/<name>.yml`) |

`stable` может ссылаться на `draft`-соседа (например, `backend.stable`
упоминает `db.draft`) — это допустимо; валидатор подсветит, но не
блокирует.

### 4. Зеркало с картой консистентно

- В `stack.md § Service map` есть строка с `name == <name>`.
- Строка в карте: `subtype` и `hosting` равны frontmatter сервиса.
- Если `hosting: external` — service-doc отсутствует (см. п.1).

Если рассинхрон — отдельный шаг: правка карты ИЛИ правка frontmatter
сервиса. Скилл предлагает через `AskUserQuestion`, не выбирает сам.

### 5. Тест-критерий явно подтверждён

В `field-checklists.md` для kind=service есть секция `Тест-критерий` с
примерами ✅/❌. Через `AskUserQuestion` скилл предъявляет архитектору
примеры и спрашивает: «какой из этих образцов ближе всего к вашему
сервису?».

Запись проходит, когда архитектор соотносит её с ✅-примером и
эксплицитно подтверждает «да, это так».

### 6. State-заметка чиста по `**blocker**`-вопросам

`state/services/<name>.md`:

- Не содержит секцию `## Открытые вопросы` ИЛИ
- Содержит, но в ней нет вопросов с префиксом/суффиксом `**blocker**`.

Не-blocker открытые вопросы при stable допустимы (например, «уточнить
retention для backup — не блокирует»). Секция `## Доменные решения` к
stable не относится — может быть. Секция `## Что копать дальше` —
обычно пуста к stable.

## Алгоритм проверки скиллом

После любой правки записи:

1. Прочитать `services/<name>.md`.
2. Прочитать `state/services/<name>.md`, если есть.
3. Прогнать пункты 1, 2, 3, 4, 6 (программно проверяемые).
4. Если все 5 ✅ — раунд `AskUserQuestion` по тест-критерию (пункт 5).
5. Если и пункт 5 ✅ — раунд `AskUserQuestion`: «Готов к stable,
   повышаем?» с опциями «Да, повысить» / «Нет, ещё не уверен» (через
   Other — что именно смущает).
6. При «Да» — Edit'ом поменять `status: draft → stable`.
7. После повышения — ещё раз `make project-check` (теперь проверит
   non-empty bodies строго).

## Что НЕ делать

- **Не повышать сам**, без подтверждения архитектора. Даже если все 6
  пунктов ✅ — спросить.
- **Не понижать `stable → draft` сам** при обнаружении проблемы — это
  смысловое решение архитектора. Можно подсветить и предложить.
- **Не считать пункт 5 пройденным «по умолчанию»**, потому что слоты
  заполнены. Тест-критерий — отдельное смысловое подтверждение.
- **Не игнорировать `**blocker**`-вопросы** — они должны быть закрыты
  или удалены до stable.
- **Не игнорировать рассинхрон с картой** (п.4) — это видимый дрейф,
  который сломает `/de-template` (карта = вход движка).
