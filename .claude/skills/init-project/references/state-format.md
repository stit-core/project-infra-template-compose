# Формат заметки `state/journey.md`

Память оркестратора онбординга — рабочее состояние пути. Не журнал.
Один файл на весь путь (нет подсущностей).

**Коммитится в git** — это shared артефакт онбординга, не приватная
память агента. Ревьюится в PR (особенно `## Cross-repo next-steps` —
финальный чеклист команде).

Заметка лежит **рядом со скиллом**:

```
.claude/skills/init-project/state/journey.md
```

## Шаблон

```markdown
---
kind: init-project-journey
---
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | `init-project-journey` | избыточная подсказка |

## Секции

Все четыре опциональны (кроме `## Текущий этап` — этот нужен пока
онбординг не закрыт).

### `## Текущий этап`

Номер этапа (1..5) + что blocking сейчас.

- Одна короткая фраза.
- После закрытия этапа — обновить номер на следующий и сбросить
  «осталось» под него.
- Если идёт возврат назад (см. `journey-stages.md § Когда возвращаться
  назад`) — указать причину: «возврат к 1: карта не содержит `redis`
  (упомянут в backend service-doc)».

### `## Открытые вопросы`

Список незакрытых смысловых вопросов по пути. Каждый — одна строка
списка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — блокирует
  текущий этап. Без префикса/суффикса — открытый, но не блокирующий.
- Закрытый вопрос **удаляется**. Если стало пусто — удалить секцию.

### `## Доменные решения`

Список неочевидных решений по пути, которые не легли в
`stack`/`services` (или в продуктовый `<org>/docs`), но важны для будущих
сессий или этапа 4. Сюда же — короткая фиксация продуктового scope,
прочитанного на этапе 1 из `<org>/docs`.

- Обычно почти пуста — ключевые решения уходят в артефакты.
- Форма: «<что выбрано> — <почему>». Без «было/стало», без дат.

### `## Cross-repo next-steps`

Накопленные next-step'ы для финала. Сюда сливается всё, что обнаружено
по пути и требует действий **вне** этого репо:

- форки бэкенда/фронта (для `hosting: external`);
- seed KV (через `/request-secret`);
- корп-онбординг (`onboard-project.sh` на корп-VPS);
- corp-handoff (через `/corp-handoff` для crowdsec, acme, otel);
- LE-DNS A-записи для сабдоменов.

На финале (этап 5) — выводится оператору списком.

## Правила жизненного цикла

- **Создаётся** в начале первого `/init-project`, если есть что
  записать (минимум `## Текущий этап`).
- **Перезаписывается** при каждом продвижении этапа.
- **Коммитится** в git — каждое продвижение этапа идёт в commit. Это
  shared контекст команды + единственный способ переживать `/clear`
  и переход между машинами.
- **Ревьюится** в Pull Request.
- **Удаляется** через `git rm`:
  - В финале (этап 5 done) — опционально, по подтверждению через
    `AskUserQuestion`. Если cross-repo next-steps ещё не сделаны —
    лучше оставить (это shared чеклист команде).
  - При `/init-project restart` — с явным `AskUserQuestion`
    подтверждением.

## Что коммитим / что НЕ коммитим

✅ Коммитим:
- Текущий этап.
- Открытые вопросы (включая `**blocker**`).
- Доменные решения по пути.
- Cross-repo next-steps (форки, seed, корп-handoff).

❌ Никогда не пишем сюда:
- Значения секретов / KV-полей.
- Содержимое `.env`, `.env.local`.
- Личные данные оператора (хост, IP, домашняя папка).

## Что НЕ хранить в заметке

- Историю изменений (это git).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого артефактов (`stack`/`services`) или продуктовых
  доков `<org>/docs` — ссылайся на них через `## Текущий этап`.
- Внутренние ответы deep-dive сессий — они в state-заметках самих
  deep-dive скиллов.
- Полные тексты прошлых вопросов оператору — только текущие открытые.
