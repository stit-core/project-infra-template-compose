# Формат заметки `state/stack.md`

Память скилла — рабочее состояние знания о stack. Не журнал. stack —
singleton, поэтому один state-файл без подкаталога.

**Коммитится в git** — это shared артефакт команды, не приватная
память агента. Ревьюится в PR как часть продуктовой документации
проекта.

Заметка лежит **рядом со скиллом**, не в `docs/project/`:

```
.claude/skills/stack-deep-dive/state/stack.md
```

Дальше — короткое `state/`, это сокращение того же пути.

## Шаблон

```markdown
---
kind: stack
ref: docs/project/stack.md
---

## Открытые вопросы
- Retention для restic — 7-4-3 или другое? (не блокирует, дефолт 7-4-3)
- crowdsec source-IP whitelist: нужен ли (нет central-LAPI пока)? (**blocker**)

## Доменные решения
- minio Console и S3 разнесены на `minio.` и `s3.`, потому что
  S3-клиенты не понимают subpath; Console на отдельном сабдомене для
  ясности доступа.

## Что копать дальше
- Уточнить acme_email с заказчиком (значение пойдёт в meta KV).
- После /service-deep-dive backend: сверить порт API в Edge.

## Host layout
- Режим: split (single-host — секцию опускаем).
- vps-app (HOST_ROLE=edge): traefik, backend, landing.
- vps-db (HOST_ROLE=db): postgres; backend достаёт PG через db.host/db.port из KV.
- vps-storage (HOST_ROLE=storage): minio, backup; restic.repository → этот хост.
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | `stack` | избыточная подсказка |
| `ref` | `docs/project/stack.md` | ссылка в редакторе |

(`name` опускаем — у stack singleton.)

## Секции

Все секции опциональны. Любая отсутствует, если содержимого нет. Первые три —
рабочая память; `## Host layout` — только при multi-host split.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка списка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — вопрос блокирует
  переход `draft → stable`. Без префикса/суффикса — открытый, но не
  блокирующий.
- Закрытый вопрос **удаляется** из секции. Если стало пусто — удалить
  всю секцию.

### `## Доменные решения`

Список неочевидных смысловых решений, которые не помещаются в md
stack'а, но важны для будущих сессий.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было X, стало Y», без дат.
- Если решение растворилось в `stack.md` — удалить отсюда (не
  дублировать).

### `## Что копать дальше`

Список локальных «следующих шагов».

- Не путать с открытыми вопросами: «копать дальше» — задача архитектора;
  «открытый вопрос» — конкретный неясный смысл.
- При выполнении шага — удалить строку. Если стало пусто — удалить
  секцию.

### `## Host layout` (опционально, multi-host split)

Раскладка `host → services` при split. Single-host (дефолт, всё на одном VPS) —
секцию **не заводим**. Появляется, когда оператор выбрал split в `§ Networks`.

- Одна строка на хост: `<имя-хоста> (HOST_ROLE=<роль>): <сервисы>`.
- Роли: `edge` (traefik/backend/landing) / `db`
  (postgres) / `storage` (minio/backup).
- Эндпоинты не дублируем: PG host/port — в KV `db`, restic — в KV
  `backup.repository`.
- Граница (репликация/HA/cross-host сеть = дело потребителя) — фиксируется как
  факт, не проектируется здесь. Детали — `references/multi-host.md`.

## Правила жизненного цикла

- **Создаётся** только когда есть что записать (хотя бы одна непустая
  секция).
- **Перезаписывается** свободно — это рабочее состояние.
- **Коммитится** в git — каждая значимая правка идёт в commit вместе с
  правкой `stack.md` (или отдельно — если правится только state).
- **Ревьюится** в Pull Request.
- **Удаляется** через `git rm`:
  - Все три секции пустые → удалить файл целиком.
  - `stack.md` удалён (откат проекта) → удалить и state.
- **Не аккумулировать** журнал.

## Что коммитим / что НЕ коммитим

✅ Коммитим:
- Открытые вопросы, доменные решения, что копать дальше.

❌ Никогда не пишем сюда:
- Значения секретов (acme_email, restic-пароль). Только
  ссылки на KV-пути.
- Содержимое `.env`, `.env.local`, rendered-конфигов.
- Личные данные оператора.

## Что НЕ хранить в заметке

- Историю изменений (это git).
- Дубликаты содержимого stack.md.
- Cross-repo next-steps, которые относятся ко всей сессии — в чате
  завершения, не в state.
- Ссылки на внешние материалы и транскрипты — это сырьё для режима B.
- Анализ service-doc'ов на рассинхрон — записывай как open-question
  «сверить с `services/<name>.md`», не копию содержимого.
