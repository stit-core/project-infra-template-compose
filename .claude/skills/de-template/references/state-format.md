# Формат заметки `state/de-template.md`

Память движка — рабочее состояние однократного прохода. Не журнал.
Существует пока de-template не закрыт (после Verify — удалить).

**Коммитится в git** — каждое «X done» идёт в коммит, чтобы прерывание
(в т.ч. /clear, переключение машины) не теряло прогресс. Ревьюится в PR
как часть онбординга.

Заметка лежит **рядом со скиллом**:

```
.claude/skills/de-template/state/de-template.md
```

## Шаблон

```markdown
---
kind: de-template-run
---

## Текущая фаза
A.3 — прунинг env-секций. Ждёт ответа оператора на каскад.

## Применённые шаги
- A.1 (COMPOSE_PROFILES=backend,postgres) — done
- A.2 (compose/minio.yml, compose/backup.yml удалены) — done

## Открытые вопросы
- A.3: судьба секции `profile backend` в `.env.example` — в карте
  backend `hosting: external`, но state/services/backend.md упоминает
  `JWT_SECRET` как «нужен для auth-flow». (**blocker**)
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | `de-template-run` | избыточная подсказка |

## Секции

Все три опциональны. Первая (`## Текущая фаза`) практически всегда
есть, пока движок активен.

### `## Текущая фаза`

Одна короткая строка: имя фазы (`A.1`/`A.2`/`A.3`/`A.4`/`A.5`/`phase-b`)
+ что сейчас blocking. После Verify — строка не пишется (движок
закрыт).

### `## Применённые шаги`

Короткий список «фаза — done». Без подробностей (они в git diff).
Используется для:

- идемпотентности (Gate.3 показывает оператору, что сделано);
- возобновления после прерывания;
- отчёта в финале.

При завершении фазы — добавить строку «<имя> done».

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка списка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — блокирует
  текущую фазу.
- Закрытый вопрос **удаляется**. Если стало пусто — удалить секцию.

Типичные случаи `**blocker**`:

- оператор сказал «Нет» в каскаде A.2/A.3 — нужен дополнительный
  контекст;
- обнаружен рассинхрон карты и compose-фрагмента;
- gate.2 (артефакт draft) обнаружился по ходу (`make project-check`
  внезапно красный).

## Правила жизненного цикла

- **Создаётся** при первом проходе фазы (или при первой остановке).
- **Перезаписывается** при каждой смене фазы.
- **Коммитится** в git между фазами (commit «chore(de-template): A.2
  done — pruned compose/{minio,backup}.yml»). Это единственный способ
  безопасно прерваться без потери прогресса.
- **Ревьюится** в Pull Request.
- **Удаляется** через `git rm`:
  - После Verify (зелёный `make validate`/`make check`) — обязательно,
    если нет открытых вопросов;
  - Если есть `**blocker**`-вопросы — оставить до их закрытия.
- **Не аккумулировать** журнал: `## Применённые шаги` — короткие
  one-liner'ы, без диффов / дат / причин (они в git log).

## Что коммитим / что НЕ коммитим

✅ Коммитим:
- Текущая фаза, применённые шаги, открытые вопросы.

❌ Никогда не пишем сюда:
- Значения секретов и переменных `.env`.
- Содержимое `.env`, `.env.local`, rendered-конфигов.
- Полные diff'ы фаз — они в `git log`/`git diff`.

## Что НЕ хранить в заметке

- Историю изменений (это git).
- Полные диффы применённых шагов (см. git diff).
- Дубликаты карты сервисов / содержимого артефактов.
- Cross-repo next-steps (они печатаются в чат в Phase B; в state нет
  смысла дублировать).
- Содержимое каскадов (показ был оператору; решение записано как
  «done» или как `**blocker**`-вопрос).
