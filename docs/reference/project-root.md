# Корень проекта

Проект живёт в одной папке — корне `~/git/<org>/`. В ней лежат все репо проекта, и из неё ведётся
вся работа: одна сессия Claude Code, которая в каждом репо работает его скиллами. Сам корень —
небольшой репо `<org>/project`: карта проекта `CLAUDE.md` и общие настройки сессии. Какие репо
бывают и как по ним идёт работа — [`ecosystem.md`](ecosystem.md).

## Что в корне

```
~/git/<org>/
├─ CLAUDE.md                карта проекта: что где лежит, как проект развивается, как здесь работать
├─ .claude/settings.json    общие запреты и настройки сессии корня
├─ .gitignore               в git корня — только его собственные файлы
├─ local/                   локальное: выгрузки, черновики, логи, временные файлы — не в git
├─ strategy/                <org>/strategy — свой git-репо
├─ infra/                   <org>/infra
└─ backend/ · frontend/ · site/ · <bot>/ · mobile/
```

- **`CLAUDE.md` — одна карта на проект.** Что где лежит, на каком этапе проект и что дальше, как в
  нём работать. Новое о проекте вносится в раздел этого файла; других документов в корне нет:
  стратегия и проектирование живут в strategy, программы сквозных задач — в infra, код — в своих
  репо.
- **Репо проекта — свои git-репо** в папках корня. `.gitignore` корня держит в git только
  `CLAUDE.md`, `.gitignore` и `.claude/settings.json`: репо проекта и `local/` в корень не попадают.
- **`local/`** — всё локальное и временное. Итог, нужный проекту, переносится в репо, которому он
  принадлежит; остальное в `local/` не хранится долго.

## Как сессия корня видит репо

Claude Code, запущенный в корне, видит репо проекта вложенными папками:

| Что в репо | Из корня |
|---|---|
| `CLAUDE.md` и правила `.claude/rules/` | подхватываются, когда сессия прочитала файл репо инструментом Read |
| скиллы `.claude/skills/` | подхватываются так же; скилл, имя которого есть в нескольких репо или совпадает со встроенной командой, зовётся с именем папки: `/infra:plan`, `/backend:smartdev` |
| агенты `.claude/agents/` | не видны: агента, которого зовёт скилл, заменяет агент общего назначения с текстом его файла |
| настройки `.claude/settings.json` — запреты и хуки | не действуют: общие запреты держит `.claude/settings.json` корня |
| git-хуки и гейты (`make check` и другие) | работают как обычно — они живут в репо |

Отсюда правила корневого `CLAUDE.md`: перед работой в репо — его `CLAUDE.md` через Read; пути репо
— от его папки; команды — в подоболочке `(cd infra && make status)`, потому что простой `cd` уводит
всю сессию в репо; коммиты — в своём репо по его правилам.

## Как завести

Корень заводится первым, до форков: с него проект начинается.

```bash
mkdir -p ~/git/<org>/.claude ~/git/<org>/local && cd ~/git/<org> && git init
# CLAUDE.md, .claude/settings.json и .gitignore — по образцам ниже: имя проекта, орга и его репо
git add -A && git commit -m "docs: корень проекта"
git clone git@<host>:<org>/strategy.git      # дальше — форки по мере появления, тоже сюда
```

Проще всего открыть `claude` в пустой папке проекта и попросить завести корень по этому документу.
Корень хранится репо `<org>/project` рядом с остальными форками: участник проекта клонирует его в
`~/git/<org>` и кладёт репо проекта внутрь.

## Образец `CLAUDE.md`

Таблицу «Что где» держат по фактическим репо проекта, раздел «Как развивается проект» — по
текущему состоянию.

````markdown
# <Проект> — корень проекта

Папка проекта `~/git/<org>/`: здесь лежат все его репо, и отсюда ведётся вся работа — стратегия,
инфра и код. Этот файл — карта проекта: что где лежит, как проект развивается и как здесь работать.
Новое о проекте вносим в нужный раздел этого файла, других документов в корне не заводим.
Устройство корня — `infra/docs/reference/project-root.md`, карта экосистемы и флоу —
`infra/docs/reference/ecosystem.md`.

## Что где

| Папка | Репо | Что там |
|---|---|---|
| `strategy/` | `<org>/strategy` | стратегия и проектирование: бизнес, продукт, домены и сервисы, ИТ-периметр, интерфейсы и экраны, FSD-карта, дизайн |
| `infra/` | `<org>/infra` | серверы и выкатка; программы сквозных задач — `infra/.claude/plans/` |
| `backend/` | `<org>/backend` | Go-сервис |
| `frontend/` | `<org>/frontend` | кабинет, React SPA |
| `site/` | `<org>/site` | индексируемый сайт, Astro |
| `<bot>/` | `<org>/<bot>` | Telegram-бот |
| `mobile/` | `<org>/mobile` | приложение Android и iOS |
| `local/` | — | локальное: выгрузки, черновики, логи, временные файлы; не в git |

Репо, которого у проекта нет, в таблице не держим; новый репо — новая строка и новая папка.

## Как развивается проект

- **Этап:** проектирование в `strategy/` → реализация → эксплуатация. Сейчас — <этап>.
- **В работе:** <что делаем сейчас и в каком репо>.
- **Дальше:** <следующие шаги>.
- **Состояние:** стратегия — `/entrypoint` (срез «где мы» по всем слоям); сквозные задачи —
  программы в `infra/.claude/plans/`; серверы — `(cd infra && make status)`.

## Как работаем

1. **Сначала проект продуман, потом код.** В `strategy/` до кода проектируется всё, что можно:
   бизнес, продукт, домены и сервисы, ИТ-периметр, интерфейсы и экраны, FSD-карта, дизайн. Код
   пишется по stable-артефактам strategy; решение о продукте, принятое по ходу, — сначала в
   strategy, потом в код.
2. **Работаем из корня.** Одна сессия — здесь, репо проекта — её вложенные папки. Независимые
   задачи — фоновым агентам, каждый в папке своего репо.
3. **В репо — его скиллами.** Перед работой в репо прочитай его `CLAUDE.md` инструментом Read:
   Claude Code подхватит правила и скиллы репо, без этого их в сессии нет. Дальше — вход и скиллы
   репо: strategy — `/entrypoint` (клиент — `/entrypoint-for-business`) и исполнители слоёв,
   артефакты strategy пишут только они; infra — `/smartdev`, `/init-project`, `/plan`; код-репо —
   `/smartdev`, `/plan`, `/scaffold`, `/release`. Скилл, имя которого есть в нескольких репо или
   совпадает со встроенной командой, зовётся с именем папки: `/infra:plan`, `/backend:smartdev`.
4. **Пути и команды репо — от его папки.** Пути в `CLAUDE.md` и скиллах репо — от корня репо:
   `.claude/plans/` в infra — это `infra/.claude/plans/`. Команды — в подоболочке:
   `(cd infra && make status)`; простой `cd` уводит всю сессию в репо.
5. **Сквозная задача — программа в infra.** Работу на несколько репо планирует `/infra:plan`: фаза
   на репо, у фазы — свой план в репо (`parent: infra:<slug>`). Выкатка — только через infra:
   `(cd infra && make bump SVC=<svc> TAG=<tag>)`.
6. **Правила репо действуют и отсюда.** Настройки репо (`.claude/settings.json`: запреты и хуки) из
   корня не применяются: общие запреты держит `.claude/settings.json` корня, а команду, которую
   репо запрещает у себя, из корня тоже не запускаем. Агенты репо (`.claude/agents/`) из корня не
   видны: скилл зовёт такого агента — запусти агента общего назначения, в промпт — текст файла
   агента и задание, модель — из поля `model` его заголовка.
7. **Коммит и push — в своём репо, по его правилам и с «да» человека.** В корне коммитятся только
   этот файл и настройки корня.
8. **Локальное — в `local/`.** Выгрузки, черновики, логи, временные файлы — туда, не в репо и не в
   корень. Итог, нужный проекту, переносим в репо, которому он принадлежит.
9. **Язык — русский.** Ответы и тексты проекта — по-русски; идентификаторы — как в репо.
````

## Образец `.claude/settings.json`

Общие запреты собраны из настроек шаблонов: обход git-хуков, переписывание истории, удаление
данных, секреты, публикация пакетов. Шаблон `*` в начале правила ловит и команду в подоболочке
`(cd infra && …)`, и форму `git -C infra …`. Автопамять выключена, как и в репо: что должно
пережить сессию, живёт в корневом `CLAUDE.md` и в репо.
